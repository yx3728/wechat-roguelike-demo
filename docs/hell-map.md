# 地狱 · 业火回魂

通关草原、击败苍岚鹿王后解锁**地狱**（`unlockBy: "mapClear"`, `unlockMapId: "grassland"`），
与草原一样在解锁前显示入口和条件（`showLocked: true`）。

> 这份文档记的是**已发货的实现**。设计稿阶段的一些数字在落地时改过（整体调难 + 一次弹幕重做），
> 差异见最后一节「落地时改了什么，为什么」。

## 一、这张图凭什么不是换皮

前四张图的玩法轴各占一格，地狱占第五格：

| 地图 | 轴 | 谁在推动战场变化 |
|---|---|---|
| 星空 | 无 | —— |
| 沙漠 | **周期性全局风险窗口**（沙暴） | 地图的计时器 |
| 海洋 | **周期性全局位移**（潮汐） | 地图的计时器 |
| 草原 | **静态地形**（草丛掩体） | 关卡布局 |
| **地狱** | **玩家自己的击杀反馈回路** | **玩家的输出速度** |

沙漠和海洋是同一类东西（一个定时器周期性地对玩家做点什么），侧风草原当年就是踩了这个坑。
草原换成了地形。地狱换成的是**回路**：**你杀得越快，场上越危险。**

这条轴顺手解决了本作的一个老问题——构筑一旦成型就压过内容。
一个 DPS 翻三倍的构筑，产出的魂火也翻三倍，清场压力同步翻三倍。**难度自己跟着构筑走。**

## 二、核心机制：业火回魂（`hellfireRevenant`）

```
杀死普通敌人 ──► 原地掉落「魂火」──► 4.5 秒引信（收缩环，可读倒计时）
                                    │
                    玩家碰到 ────────┤────── 引信烧完
                        │                        │
                     「镇魂」                  「回魂」
                   +1 层业火                 原地爬起一只亡魂
```

| 元素 | 数值 | 说明 |
|---|---|---|
| 魂火引信 | **4.5 秒**（焦骨掉的只有 **3.0 秒**） | 收缩环 + 中心亮度衰减，两条冗余读数 |
| 镇魂判定 | 玩家中心 **28 px** 内 | `hell_draw` 可扩到 98 px |
| 业火层 | 上限 **6 层**，每层 **+7% 主炮伤害** | 每层独立 **4.0 秒**计时，不是整体刷新 |
| 亡魂 | 源敌人 **45% 生命**，只有接触伤害，移速 **1.8×** | **击杀亡魂不再掉魂火** —— 回路到此为止，不会无限递归 |
| 场上魂火上限 | **14 个** | 超出时最老的一个立即回魂 |
| 场上亡魂上限 | **8 只** | 上限期间新的魂火直接消散（不惩罚已经被淹的玩家） |

后两条上限是**安全栏**：无论玩家 DPS 多离谱，场面都有天花板。
`tests/hell.test.js` 里有一条用例专门按"每帧杀一只"跑 400 帧来锁这两个上限。

业火不是被动收益，是**连击表**：停手 4 秒就掉一层。它奖励的是"边打边收"。

Boss 战期间**回路照常运行**（沙暴是挂起的）。理由：这不是天气，是玩家自己的经济，
而且阎罗的招式会主动利用它。

## 三、颜色系统：地狱是全作唯一「本体没有颜色」的地图

**过程。** 现有 30 个敌人配色两两最近的六对是 ΔE 0.014 / 0.020 / 0.031 / 0.039 / 0.045 / 0.047（OKLab）——
同族内部本来就故意接近。真正的问题是**跨图**：把整个 sRGB 按 8 步网格搜一遍，
在"够亮（relL ≥ 0.18）+ 有色相身份（chroma ≥ 0.10）+ 在地狱底色上对比 ≥ 4.5:1"三个约束下，
**离所有旧敌人色最远的候选也只有 ΔE 0.151**；要凑够六条互相也分得开的，会掉到 ΔE 0.099。

也就是说：**高饱和色相这条路已经走满了，再找"一个没用过的颜色"是找不到的。**

**结论。** 地狱不按色相区分，按**明度结构**区分：

- 现有 30 个敌人色里，亮度 relL < 0.12 的只有 **1 个**，彩度 < 0.05 的只有 **3 个**。
- 所以地狱独占**暗 + 无彩**这条车道：**焦黑本体（relL ≤ 0.017）+ 白热轮廓光**。
- 轮廓光负责可读性（对最差底色 **10.5–14.7:1**），本体负责"这是地狱的怪"。
- **全图仅有的高饱和色被留给危险**：预警红 `#ff3b30`、魂火橙 `#ffa000`、亡魂 `#ff6b3d`。

轮廓光最高彩度 **0.030**，危险色最低彩度 **0.172**——**5.7 倍差距**。
所以在地狱有一条硬约定：**看见颜色，就是看见伤害。**

| 用途 | 本体 | 轮廓光 | 本体 relL | 轮廓光最差底色对比 | 距最近旧敌人色 |
|---|---|---|---|---|---|
| 焦骨 | `#1f1c22` | `#e8e2d6` | 0.012 | 11.4:1 | ΔE 0.195 |
| 拾魂者 | `#26201c` | `#e4dcc8` | 0.015 | 10.8:1 | ΔE 0.197 |
| 烙印使 | `#1c1f24` | `#dce6f0` | 0.014 | 11.7:1 | ΔE 0.190 |
| 锁魂 | `#231d20` | `#ded6e8` | 0.013 | 10.5:1 | ΔE 0.196 |
| 炉喉 | `#201e1a` | `#f0e8d2` | 0.013 | 12.1:1 | ΔE 0.204 |
| 刑官（精英） | `#2a2026` | `#fbf4e4` | 0.017 | 13.5:1 | ΔE 0.181 |
| 阎罗（Boss） | `#171418` | `#ffffff` | 0.007 | 14.7:1 | ΔE 0.225 |

ΔE 0.18–0.22 是已发货同族间距（0.014）的 **13–16 倍**，而且落在旧敌人从没进过的亮度区间。

底色（`themes`，按波次循环）：

| 波次 | bg | ripple | star | 场景 |
|---|---|---|---|---|
| 一 | `#241f2b` | `#2e2736` | `#c9b8d6` | 熄炉——冷却的渣土，灰在飘 |
| 二 | `#2c2622` | `#382f29` | `#d8c6ae` | 焦土——烧透的地面裂开细纹 |
| 三 | `#1d2620` | `#26332c` | `#b3c9bb` | 硫沼——绿灰的沼气与骨屑 |
| 四 | `#332330` | `#402c3c` | `#dcbcd2` | 裂隙——底下有东西在亮 |

地狱敌人**不走图集**：焦黑本体 + 轮廓光是直接画的（`hellVisuals.js`），不是贴图换皮。
`tests/texture-coverage.test.js` 为此分出 procedural 分支——它们必须被自己的绘制模块认领，
且一张图片都不加载，贴图开关对它们天然成立。

## 四、地狱生物

每种敌人开火前都有名为 `warn` 的预警相——视觉层只按这个名字画预警圈，
**预警期间本体不位移、锁定目标不变**。

| 名称 | 注册 id | 预警 | 行为 |
|---|---|---|---|
| 焦骨 | `cinderHusk` | 1200 ms | 基础兵，单发瞄准射击。**它掉的魂火引信只有 3.0 秒**——教玩家"这个得马上去收"。 |
| 拾魂者 | `soulPicker` | 不攻击 | 完全不打玩家，**径直飞向最近的魂火并吃掉它**。每吃一个 +30% 生命并变大，自己死后的引信延到 **8.0 秒**。本作第一个跟玩家抢资源的敌人。 |
| 烙印使 | `brandBearer` | 900 ms | 在**玩家当时**的位置烙下印记，**1.1 秒**后炸开。转折：**印记落在魂火上会直接点燃它**。躲的时候还得管往哪躲。 |
| 锁魂 | `chainWarden` | 1000 ms | 甩出锁链，把玩家**朝最近的魂火拖 2.2 秒**（118 px/s）。看起来在帮你，实际是把你拽进别人的弹道。 |
| 炉喉 | `forgeGullet` | 1300 ms | 固定炮台，推出 **3 颗慢速炉火**；炉火**不出屏消失**，飞 **3.0 秒**后停在原地再烧 **2.6 秒**。 |
| 刑官（精英） | `warden` | 850 ms（扇形齐射） | 光环（半径 **132 px**）内**所有魂火引信按 2× 速度烧**。死亡时全场引信统一跳到**剩余 1.5 秒**——够你收掉身边几个，不够收完全场。**什么时候杀它是个决策，不是陷阱。** |
| 亡魂 | `revenant` | 起身 420 ms | 只有接触伤害。起身相是可读窗口，不是无敌帧。 |

## 五、Boss：阎罗（`yama`）

### 罪值：难度由玩家在这场战斗里的表现决定

罪值 0–100，开局 20：**回魂 +15，镇魂 −6**。它不改血量、不改伤害，改的是**招式池和承伤**：

| 罪值 | 招式池 | 阎罗承伤 |
|---|---|---|
| **< 32（低罪）** | 只有「锁刑」 | **×1.30** |
| **≥ 32（高罪）** | 锁刑 + 「业火判决」 | ×1.0 |
| **= 100（满罪）** | 立刻打出「无间」，之后罪值重置为 50 | ×1.0 |

罪值不做独立 UI 条：**直接画在阎罗身上**——轮廓光的亮度随罪值升高，满罪时白到刺眼。

二阶段（生命 50%，转场硬直 **1.2 秒**）：罪值下降速度 **×0.6**（镇魂只减 3.6）。

实测两条路都成立（端到端跑真实战斗）：
- **打得干净**：33 次镇魂 / 0 次回魂，罪值全程 0–20，阎罗只用锁刑且一直吃 ×1.30
- **打得脏**：0 次镇魂 / 15 次回魂，罪值 20–100，三招全部登场

### 三个招式与可解性验算

玩家是**手指直接拖拽**（`battle.js` 的 `onTouchMove` 没有速度上限），
下面按"可控拖动 700 px/s"这个保守值验算。**这些数字是从真实发射出来的子弹量出来的，不是公式推的**，
并且由 `tests/hell.test.js` 的「锁刑」用例长期锁住。

**锁刑 `sentence`** —— 预警 1000 ms（二阶段 850），冷却 7.5 秒（二阶段 6.2 秒）。
一道道**平行下落的弹幕墙**，中间留一道缺口，缺口在左右两侧之间来回摆。

| | 一阶段 | 二阶段 |
|---|---|---|
| 墙数 / 间隔 | 4 道 / 620 ms | 6 道 / 480 ms |
| 缺口摆幅 | ±110 px | ±140 px |
| 缺口宽度（每一行都一样） | **63 px** = 玩家宽度 1.97 倍 | **63 px** |
| 缺口横移 | 209 px 需 299 ms | 273 px 需 390 ms |
| **余量** | **299 ms** | **61 ms** |

63 px 落在已发货 Boss 走廊 **45–89 px** 的紧端。二阶段 61 ms 的余量是全作最紧的一处。

**业火判决 `hellfireVerdict`** —— 罪值 ≥ 32 解锁，预警 1200 ms，冷却 14 秒（二阶段 11 秒）。
场上现存魂火**按距玩家由近及远依次点燃**（间隔 350 ms）。
它不产生新弹幕，**它把你欠的账一次性收走**。场上没有魂火时评分归零，不会空放。

**无间 `avici`** —— 罪值满时打出，预警 **1500 ms**，判决持续 420 ms，冷却 16 秒。
屏幕划成 3×4 共 12 格，只有 **2 格**安全（单格 130 × 211 px）。

硬约束：**两个安全格中至少一个与玩家当前所在格相邻（含斜向）**。
最坏位移因此永远只有 **248 px**，1500 ms 内需要 **165 px/s** —— 拖得再慢也有解。
另一个安全格可以放远，留给读得快、想主动换位的玩家。测试遍历玩家可能站的全部 12 格 × 各 40 次抽样。

难的是在 1.5 秒里读懂 12 格里哪两格安全，不是"能不能走到"。

击败后直接胜利。Boss 基础金币 **1400**，不连接隐藏虚空线。

## 六、六个专属海克斯

| 品质 | 名称 / id | 精确效果 |
|---|---|---|
| 蓝 | 引魂 `hell_draw` | 镇魂判定半径 **28 → 98 px**，走近即收。 |
| 蓝 | 缓刑 `hell_reprieve` | 所有魂火引信 **+2.0 秒**；现存与新掉落的都生效。 |
| 绿 | 余烬不熄 `hell_emberhold` | 业火层上限 **6 → 9**，每层计时 **4.0 → 5.5 秒**。 |
| 紫 | 镇魂爆 `hell_quell` | 每次镇魂在原地炸开，对 **90 px** 内敌人造成当前主炮伤害 **×2.5**。 |
| 橙 | 无罪 `hell_absolution` | 业火满层时免疫一次伤害，触发后清空全部业火层，冷却 **12 秒**。 |
| 蓝 | 赦令 `hell_pardon` | 击杀亡魂返还 **1 层业火**——让"没打扫干净"仍有回收路径。 |

`hell_absolution` 是这条线的橙卡：它把业火从"输出增益"变成"一条命"，
于是玩家要在"留着满层保命"和"继续叠层输出"之间取舍。

地狱资源最紧：普通敌人经验球 **50%** 概率，道具率 **×0.25**。

## 八、落地时改了什么，为什么

**整体调难**（"这一章的难度高一些"）：

| 项 | 设计稿 | 发货 |
|---|---|---|
| 魂火引信 | 6.0 秒 | **4.5 秒**（焦骨 4.0 → **3.0**） |
| 亡魂 | 35% 生命 / 1.6× 速 | **45% 生命 / 1.8× 速** |
| 场上上限 | 10 魂火 / 6 亡魂 | **14 / 8** |
| 业火 | +8%/层，每层 5.0 秒 | **+7%/层，每层 4.0 秒** |
| 罪值 | +12 / −8，阈值 40 | **+15 / −6，阈值 32** |
| 低罪承伤 | ×1.35 | **×1.30** |
| 无间预警 | 1800 ms | **1500 ms** |

**锁刑整个重做了一次。** 设计稿写的是"整圈旋转环，58 发缺口 3 格"。
按公式算出来是 87 px 走廊、看着没问题；但**把真实发射出来的子弹量一遍**才发现两个错：

1. 抠掉 k 发子弹留下的是 **k+1 格**的缺口，不是 k 格——实际走廊 83 px，比目标宽。
2. 更要命的是**几何本身不成立**：竖屏里 Boss 在上、玩家在下，整圈弹幕的缺口一旦转到侧面，
   玩家那一排就是一堵没有缺口的墙。实测二阶段连续两环的缺口错开到 136°，
   玩家需要横移 1770 ms 而只有 448 ms——**不是难，是无解**。

改成**朝下的平行弹幕墙**：缺口的屏幕横坐标成了玩家要读的唯一变量，
每一行的缺口宽度都一样（放射扇形在玩家上方 200 px 处只剩 34 px，等于"站得靠上就必吃伤害"），
缺口**左右来回摆**而不是单向转走（单向转走会让第 N 道离第 N−1 道越来越远）。
现在的数字全部是量出来的，并且写进了测试。
